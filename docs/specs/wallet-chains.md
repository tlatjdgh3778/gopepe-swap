# 스펙: wallet-chains (지갑 연결·체인 config·체인 전환)

- 상태: 완료
- 최종 갱신: 2026-11-07

## 1. 목표

Ethereum(1), Base(8453), Arbitrum(42161) 메인넷용 Uniswap V3 단일 홉 스왑 UI의 기반을 만든다. 사용자는 브라우저 지갑을 연결하고 체인을 선택하며, 이후 기능은 체인별 config와 RPC 프록시, mock 커넥터 + anvil 포크 E2E 환경 위에 올라간다. [사용자 결정]

### 1.1 화면

- 헤더(텍스트 워드마크, 체인 드롭다운, 지갑 버튼), 스왑 카드 뼈대, 주 버튼으로 구성한다 [제안 후 승인]
- 연결 후 지갑 버튼은 줄인 주소를 표시하고, 메뉴에서 연결을 해제한다 [제안 후 승인]
- 주 버튼은 스왑 카드 하단의 전체 너비 버튼이며, 위에서부터 먼저 해당하는 상태를 표시한다: 복원 중(로딩 표시, 비활성) [사용자 결정], 지갑 미연결(`지갑 연결`, 연결 모달 열기) [제안 후 승인], 그 외(`금액 입력`, 비활성) [제안 후 승인]
- 앱은 저장된 연결 유무와 상관없이 복원 중 상태로 시작하고, 복원이 끝나면 연결 또는 미연결 상태로 바뀐다 [사용자 결정]
- 복원 중 지갑 버튼은 로딩 표시, 비활성이다 [제안 후 승인]
- 시간 제한 후 복원이 늦게 성공하면 연결 상태로 바뀐다 [제안 후 승인]
- 디자인은 `docs/design/README.md`를 따른다 [사용자 결정]

### 1.2 지갑과 체인

- 지갑은 wagmi 3 + 자체 UI로 만들고, EIP-6963으로 감지한 브라우저 지갑을 지원한다 [제안 후 승인]
- SSR은 wagmi `cookieStorage` + `ssr: true`를 쓴다 [제안 후 승인]
- 드롭다운은 앱의 선택 체인만 바꾸며, 선택 체인이 앱의 기준이다 [제안 후 승인]
- 별도의 전환 버튼 상태를 두지 않고, 트랜잭션 전송 직전에 앱에 연결된 체인을 선택 체인으로 자동 전환한다 [사용자 결정]

### 1.3 테스트 환경과 정리

- E2E는 mock 커넥터 + Ethereum 포크 1개로 구성한다. 원본 체인 ID를 유지하고 포크 블록을 상수로 고정한다 [사용자 결정]
- E2E에서 프록시의 Ethereum 대상(업체 RPC와 공개 RPC 모두)과 mock 커넥터가 쓰는 `chain.rpcUrls`를 anvil로 맞춘다 [제안 후 승인]
- E2E는 전용 `distDir`과 전용 포트를 쓴다 [제안 후 승인]
- CI `e2e` 잡에 Foundry를 설치하고 Ethereum용 RPC 시크릿 1개를 쓴다. 시크릿이 없으면 잡이 실패한다 [제안 후 승인]
- 프록시는 `app/api/rpc/[chainId]/route.ts`에 둔다 [제안 후 승인]
- `tsconfig.json`의 `target`을 ES2020으로 올린다 [제안 후 승인]
- `app/page.tsx`와 기존 테스트 2개를 교체하고, `metadata`를 GOPEPE Swap으로, `lang`을 `ko`로 바꾼다 [제안 후 승인]

## 4. 인터페이스 계약

### 4.1 RPC 프록시

- 경로와 형식: `POST /api/rpc/[chainId]`, 표준 JSON-RPC 단일 요청 또는 배치 [사용자 결정]
- 지원 chainId: 1, 8453, 42161 [제안 후 승인]
- 허용 메서드: `eth_chainId`, `eth_blockNumber`, `eth_getBlockByNumber`, `eth_call`, `eth_getBalance`, `eth_getCode`, `eth_estimateGas`, `eth_gasPrice`, `eth_maxPriorityFeePerGas`, `eth_feeHistory`, `eth_getTransactionByHash`, `eth_getTransactionReceipt`, `eth_getTransactionCount` [제안 후 승인]
- 지원하지 않는 chainId 응답: HTTP 404 [제안 후 승인]
- 다른 사이트의 요청 또는 Origin 없는 요청의 응답: HTTP 403. 같은 사이트 판정은 Origin과 Host(또는 X-Forwarded-Host)를 포트까지 비교한다 [제안 후 승인]
- 본문 1MB(1,048,576바이트) 초과 응답: HTTP 413 [제안 후 승인]
- 배치 50개 초과 응답: HTTP 400 [제안 후 승인]
- JSON 형식 오류와 JSON-RPC가 아닌 입력(`{}`, `[]`, `method` 없음)의 응답: HTTP 400 [제안 후 승인]
- 허용 외 메서드 응답: HTTP 200 + JSON-RPC 오류 코드 `-32601`. 배치에 하나라도 포함되면 배치 전체를 거절하고 오류 객체 하나를 돌려준다 [제안 후 승인]
- 거절 판정 순서: chainId, Origin, 크기, JSON 형식, 배치 개수, 메서드 [제안 후 승인]
- 공개 RPC: 체인별 viem 기본 RPC 1개. 업체 RPC와 공개 RPC의 시간 제한은 각 5초다 [제안 후 승인]
- 모든 RPC 실패 응답: HTTP 502 [제안 후 승인]
- 업체가 HTTP 200으로 JSON-RPC가 아닌 JSON을 주면 그대로 돌려주되, 업체 URL과 키는 가린다 [제안 후 승인]
- 트랜잭션 전송은 프록시를 거치지 않고 사용자 지갑이 처리한다 [제안 후 승인]

### 4.2 환경 변수·쿠키

- 서버 전용 RPC 변수: `ETH_MAINNET_RPC_URL`, `BASE_MAINNET_RPC_URL`, `ARB_MAINNET_RPC_URL` [제안 후 승인]
- `.env.example`: 키 없이 변수 이름만 담아 커밋하고, `.gitignore`에 `!.env.example`을 추가한다 [제안 후 승인]
- E2E 플래그: `NEXT_PUBLIC_E2E_MOCK=1`일 때만 mock 커넥터를 포함하고, 이 값은 Playwright 설정과 `check:build`의 E2E 빌드 대조에서만 전달한다 [제안 후 승인]
- 선택 체인 쿠키: 이름 `gopepe-chain`, 값은 chainId, 기본값은 Ethereum [제안 후 승인]

### 4.3 체인·컨트랙트·토큰 config

- 컨트랙트 주소: 체인별 QuoterV2, Factory, WETH. 코드에 넣기 전에 Uniswap 공식 배포 문서와 대조한다 [제안 후 승인]
- 토큰 원본: Uniswap 공식 Token List(`tokens.uniswap.org`)에서 세 체인만 걸러 만든 스냅샷. 생성 스크립트는 `scripts/`, 체인별 JSON은 `config/`에 커밋한다 [제안 후 승인]
- 토큰 필드: `chainId`, `address`, `name`, `symbol`, `decimals`, `logoURI`. 키는 `chainId` + `address`다 [제안 후 승인]
- 고정 토큰: ETH, WETH, USDC, USDT, DAI. 리스트에 없는 네이티브 ETH 항목과 고정 정보는 코드로 추가하고, 체인별 고정 토큰 목록을 별도로 제공한다 [제안 후 승인]
- 네이티브 ETH: 주소 `0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE`, decimals 18 [제안 후 승인]
- Arbitrum USDT: 리스트의 `USDT0` 주소 `0xFd086bC7CD5C481DCC9C85ebE478A1C0b69FCbb9`를 고정 토큰으로 쓰고 심볼은 `USDT`로 표시한다 [제안 후 승인]
- `logoURI`는 선택 필드이고, 없으면 심볼 글자로 표시한다 [제안 후 승인]

### 4.4 체인 전환 훅

- 형태: `useEnsureChain()`은 비동기 함수 `ensureChain()`을 돌려주고, 이 함수는 전환이 끝나면 resolve한다. 이미 선택 체인이면 지갑 요청 없이 resolve한다 [제안 후 승인]
- 기반: wagmi `useSwitchChain` [사용자 결정]
- 오류: 거부, 실패, 미연결 상태의 호출은 reject로 알린다 [제안 후 승인]

## 5. 엣지 케이스와 실패 시나리오

### 5.1 지갑

- EC-1: 브라우저 지갑이 없으면 모달에 안내와 MetaMask 설치 링크를 표시한다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- EC-2: 연결 요청 거부나 연결 오류가 나면 미연결 상태를 유지한다 — 검증: E2E (mock 커넥터 `connectError`) [제안 후 승인]
- EC-3: 체인 전환을 거부하면 선택 체인과 연결된 체인을 그대로 두고 훅이 오류를 돌려준다 — 검증: 통합 테스트 (mock 커넥터 `switchChainError`) [사용자 결정]
- EC-4: 지갑에 해당 체인이 없으면 체인 추가까지 시도한다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- EC-5: 지갑 쪽에서 체인이 바뀌어도(비지원 체인 포함) 선택 체인은 유지한다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]

### 5.2 복원과 저장값

- EC-6: 복원에 실패하거나 5000ms 안에 끝나지 않으면 미연결 상태로 표시한다. 시간 값은 상수로 둔다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- EC-7: 체인 쿠키가 없거나 값이 잘못되면 Ethereum으로 처리한다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]

### 5.3 RPC 프록시

- EC-8: §4.1의 거절 조건에 해당하는 요청은 업체로 전달하지 않고 §4.1의 응답을 돌려준다 — 검증: 통합 테스트 (업체 RPC는 스텁) [제안 후 승인]
- EC-9: 네트워크 오류, 시간 초과, HTTP 4xx·5xx(JSON-RPC 오류 본문을 담은 경우 포함), JSON이 아닌 응답, 환경 변수 없음(빈 값 포함)이면 공개 RPC로 넘긴다 — 검증: 통합 테스트 (업체 RPC는 스텁) [제안 후 승인]
- EC-10: HTTP 200으로 받은 revert 같은 JSON-RPC 오류는 fallback 없이 돌려주되, EC-12의 값만 가린다 — 검증: 통합 테스트 (업체 RPC는 스텁) [제안 후 승인]
- EC-11: 모든 RPC가 실패하면 §4.1의 응답을 돌려준다 — 검증: 통합 테스트 (업체 RPC는 스텁) [제안 후 승인]
- EC-12: 응답, 오류 메시지, 로그에 업체 URL과 키가 나오지 않는다 — 검증: 통합 테스트 (업체 RPC는 스텁) [제안 후 승인]
- EC-13: 업체 호출 실패(네트워크 오류, 시간 초과, HTTP 4xx·5xx, JSON이 아닌 응답)로 공개 RPC로 넘기면 서버 로그에 경고를 남긴다. 환경 변수 없음은 제외한다 — 검증: 통합 테스트 (업체 RPC는 스텁) [제안 후 승인]
