# 스펙: token-amount-input (토큰 선택·잔액·금액 입력)

- 상태: 완료
- 최종 갱신: 2026-11-10

## 1. 목표

스왑 카드에서 보낼 토큰·금액과 받을 토큰을 정하는 입력부를 만든다. 사용자는 선택 체인의 토큰 목록에서 토큰을 고르고, 잔액을 보며 보낼 금액을 입력한다. 이 입력 상태는 F3 견적이 읽는 계약(§4.3)이 된다. [제안 후 승인]

### 1.1 화면

- 스왑 카드는 보내는 칸(토큰 버튼, 금액 입력, 잔액, `최대`), 뒤집기 버튼, 받는 칸(토큰 버튼, 금액 칸, 잔액), 주 버튼으로 구성한다 [제안 후 승인]
- 받는 칸의 금액 칸은 읽기 전용이며 F3 견적 결과를 표시하는 자리다 [제안 후 승인]
- 토큰 모달은 검색 입력과 토큰 목록(로고, 심볼, 이름, 잔액, 선택 표시)으로 구성한다 [제안 후 승인]
- 토큰 모달의 목록 영역은 고정 높이다. 검색 반영 대기 중, 결과가 적을 때, 결과가 없을 때 모두 같다 [사용자 결정]
- 스왑 카드 최대 폭은 560px, 보내는·받는 칸 금액 글자 크기는 28px이다. 입력칸보다 긴 금액은 입력칸 안에서 가로 스크롤된다 [사용자 결정]
- 헤더 체인 드롭다운의 버튼(선택 체인)과 목록 항목에 체인 아이콘을 표시한다. 아이콘을 불러오지 못하면 체인 이름 첫 글자로 대체한다 [사용자 결정]
- 주 버튼 문구: `select-token`은 `토큰 선택`, `enter-amount`는 `금액 입력`, `insufficient-balance`는 `잔액 부족` [제안 후 승인]
- 주 버튼 문구: `input-valid`는 `금액 입력`이다. F3부터 이 상태를 견적 상태가 대체한다 [사용자 결정]
- 주 버튼은 연결 상태에서 `select-token`, `enter-amount`, `insufficient-balance`, `input-valid` 순으로 먼저 해당하는 상태를 표시한다 [제안 후 승인]
- ETH `최대`의 체인별 가스 예약량: Ethereum 0.005 ETH, Base 0.0005 ETH, Arbitrum 0.0005 ETH [제안 후 승인]

## 2. 비목표

- 블록마다 잔액 갱신, 토큰 모달이 열린 동안 잔액 갱신 [제안 후 승인]

- 견적·예상 수령량 (F3), 스왑 후 잔액 갱신 (F5·F6), ETH ↔ WETH 분기 (F7) [제안 후 승인]
- Base·Arbitrum 포크 자동 테스트 [제안 후 승인]

## 3. 완료의 정의

### 3.1 초기 상태와 토큰 선택

- DoD-1: 페이지를 열면 보내는 토큰은 선택 체인의 ETH, 받는 토큰은 미선택, 금액은 빈 값이다 — 검증: 통합 테스트 [사용자 결정]
- DoD-2: 서버 렌더링 HTML의 토큰·금액 초기값이 DoD-1과 같다 — 검증: E2E (SSR HTML) [제안 후 승인]
- DoD-3: 토큰 버튼을 누르면 그 칸의 토큰 모달이 열린다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-4: 토큰 모달 목록은 선택 체인의 토큰만 담는다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-5: 모달에서 토큰을 고르면 그 칸에 반영되고 모달이 닫힌다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-6: 반대쪽 칸에 선택된 토큰을 고르면 두 칸의 토큰이 맞바뀐다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-7: 뒤집기 버튼을 누르면 두 칸의 토큰이 미선택을 포함해 그대로 맞바뀐다 — 검증: 통합 테스트, E2E [제안 후 승인]
- DoD-8: DoD-6의 맞바꿈이나 DoD-7의 뒤집기 후 금액은 빈 값이 된다 — 검증: 통합 테스트 [제안 후 승인]

### 3.2 목록 정렬과 검색

- DoD-9: 연결 상태의 모달 목록은 고정 토큰 5개(ETH, WETH, USDC, USDT, DAI 순서), 잔액이 0보다 큰 토큰, 나머지 토큰 순으로 놓인다 — 검증: 단위 테스트, E2E (잔액 주입) [제안 후 승인]
- DoD-10: 잔액이 있는 토큰 그룹과 나머지 그룹 안에서는 대소문자를 무시한 심볼순, 심볼이 같으면 소문자로 바꾼 주소 문자열순이다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-11: 앞뒤 공백을 지운 검색어로 심볼과 이름에 대소문자를 무시한 부분 일치로 목록을 거른다 — 검증: 단위 테스트, 통합 테스트 [사용자 결정]
- DoD-12: 검색 중에도 DoD-9·DoD-10의 순서를 유지한다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-41: 검색어 입력이 멈춘 뒤 250ms가 지나면 목록에 반영한다 — 검증: 통합 테스트 (가짜 타이머) [사용자 결정]
- DoD-42: 검색어를 입력한 뒤 목록에 반영되기 전까지 목록 자리에 스켈레톤 행을 표시한다 — 검증: 통합 테스트 [사용자 결정]

### 3.3 잔액

- DoD-13: 연결 상태에서 두 칸에 선택 토큰의 잔액을 선택 체인 기준으로 표시한다 — 검증: E2E (ETH, 주입한 USDC) [제안 후 승인]
- DoD-14: 모달의 각 행에 그 토큰의 잔액을 표시한다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-15: 잔액 표시는 소수 최대 4자리 버림, 끝의 0 제거, 천 단위 쉼표, 소수점 마침표이며 로캘에 따라 달라지지 않는다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-16: 잔액이 0보다 크고 0.0001보다 작으면 `<0.0001`, 0이면 `0`으로 표시한다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-17: 카드 잔액을 15초마다 다시 읽는다. 브라우저 탭이 숨겨진 동안에는 주기 읽기를 하지 않는다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- DoD-18: 창에 포커스가 돌아오면 카드 잔액을 다시 읽는다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- DoD-19: 계정, 선택 체인, 선택 토큰이 바뀌면 카드 잔액을 다시 읽는다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- DoD-20: 모달을 열 때마다 목록 전체 잔액을 다시 읽는다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- DoD-21: 같은 계정·체인에서 새로고침 전에 읽은 모달 잔액이 있으면 새 읽기가 끝나기 전에 그 값을 표시한다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- DoD-22: 요청이 성공하는 경로에서 모달을 한 번 열 때 ERC-20 잔액 읽기 요청은 `eth_call` 2회 이하다 — 검증: 통합 테스트 (RPC fetch 스텁으로 요청 수 집계) [제안 후 승인]
- DoD-23: 요청이 성공하는 경로에서 모달을 한 번 열 때 네이티브 ETH 잔액 읽기 요청은 `eth_getBalance` 1회다 — 검증: 통합 테스트 (RPC fetch 스텁으로 요청 수 집계) [제안 후 승인]
- DoD-24: Ethereum 포크에서 스냅샷 토큰 484개의 잔액 일괄 읽기가 RPC 프록시를 거쳐 성공한다 — 검증: 통합 테스트 (실제 anvil 포크, `test:fork`) [제안 후 승인]
- DoD-25: Base 메인넷에서 카드 잔액 표시와 모달 정렬이 동작한다 — 검증: 수동 1회, 결과 기록 [제안 후 승인]
- DoD-26: Arbitrum 메인넷에서 카드 잔액 표시와 모달 정렬이 동작한다 — 검증: 수동 1회, 결과 기록 [제안 후 승인]

### 3.4 금액 입력과 `최대`

- DoD-27: 숫자와 소수점 하나로 된 입력을 금액에 반영한다 — 검증: 단위 테스트, 통합 테스트 [제안 후 승인]
- DoD-28: 입력한 쉼표는 소수점으로 바뀌어 반영된다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-29: 모달에서 보내는 토큰을 다른 토큰으로 바꾸면 금액을 유지하고, 새 토큰 decimals를 넘는 소수 자릿수를 반올림 없이 잘라낸다 — 검증: 단위 테스트, 통합 테스트 [제안 후 승인]
- DoD-30: ERC-20의 `최대`는 잔액 전체를 정밀도 손실 없이 금액에 넣는다 — 검증: 단위 테스트, E2E (주입한 USDC) [제안 후 승인]
- DoD-31: ETH의 `최대`는 잔액에서 선택 체인의 가스 예약량을 뺀 값을 넣는다 — 검증: 단위 테스트, E2E [제안 후 승인]
- DoD-32: `최대`가 넣는 문자열은 천 단위 쉼표가 없고 끝의 0을 지운 값이며, 소수부가 모두 0이면 소수점도 지운다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-33: 받는 칸 금액 칸은 사용자 입력을 받지 않는다 — 검증: 통합 테스트 [제안 후 승인]

### 3.5 주 버튼

- DoD-34: 복원 중·미연결 상태는 F1 동작대로 F2 상태보다 앞선다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-35: 연결 상태에서 두 칸 중 하나라도 토큰이 미선택이면 `select-token`, 비활성이다 — 검증: 통합 테스트, E2E [제안 후 승인]
- DoD-36: 두 토큰이 선택되고 금액이 비었거나 0이면 `enter-amount`, 비활성이다 — 검증: 통합 테스트, E2E [제안 후 승인]
- DoD-37: 금액이 보내는 토큰 잔액보다 크면 `insufficient-balance`, 비활성이다 — 검증: 통합 테스트, E2E [제안 후 승인]
- DoD-38: DoD-35~37에 해당하지 않으면 `input-valid`, 비활성이다 — 검증: 통합 테스트, E2E [사용자 결정]

## 4. 인터페이스 계약

### 4.1 주 버튼

- `data-testid="primary-button"`의 `data-state` 값: `restoring` | `disconnected` | `select-token` | `enter-amount` | `insufficient-balance` | `input-valid`. F1의 `ready`는 쓰지 않는다 [제안 후 승인]

### 4.2 테스트 식별자

- `token-field[data-side="in"|"out"]`: 보내는 칸(`in`)과 받는 칸(`out`) [제안 후 승인]
- `token-button[data-token-address]`: 칸 안의 토큰 버튼. 미선택이면 값은 빈 문자열이다 [제안 후 승인]
- `amount-input`: 칸 안의 금액 칸. `out` 칸에서는 읽기 전용이다 [제안 후 승인]
- `balance[data-balance-raw]`: 칸 안의 잔액. 값은 정수 잔액의 10진 문자열이며, 잔액을 모르거나 미연결이면 속성이 없다 [제안 후 승인]
- `max-button`: `in` 칸에만 있다 [제안 후 승인]
- `flip-button` [제안 후 승인]
- `token-modal[data-side]`: 모달을 연 칸 [제안 후 승인]
- `token-search`: 모달 검색 입력 [제안 후 승인]
- `token-option[data-token-address][data-selected][data-balance-raw]`: 모달 행. `data-selected`는 모달을 연 칸의 현재 토큰 행만 `true`이고 나머지는 `false`다. `data-balance-raw` 규칙은 `balance`와 같다 [제안 후 승인]
- `token-logo[data-fallback="true"|"false"]`: 모달 행과 카드 토큰 버튼 안의 로고. 심볼 글자로 대체하면 `true`다 [제안 후 승인]
- `token-search-empty`: 검색 결과 없음 표시 [제안 후 승인]
- `token-list-skeleton`: 검색 반영 대기 중 목록 자리의 스켈레톤 [제안 후 승인]

### 4.3 입력 상태

- 클라이언트 컨텍스트 훅 `useSwapForm()`은 `{ chainId: SupportedChainId; tokenIn: Token | null; tokenOut: Token | null; amountIn: string; amountInRaw: bigint | null }`를 돌려준다 [제안 후 승인]
- `amountInRaw`는 `amountIn`을 `tokenIn.decimals`로 변환한 정수다. `tokenIn`이 없거나 `amountIn`이 비었거나 `.`이면 `null`, 값이 0이면 `0n`이다 [제안 후 승인]
- 상태를 바꾸는 함수는 계약에 포함하지 않는다 [제안 후 승인]

### 4.4 config·lib

- `config/`의 `GAS_RESERVE_BY_CHAIN`: 키는 `SupportedChainId`, 값은 wei 단위 `bigint`. 1 → `5_000_000_000_000_000n`, 8453 → `500_000_000_000_000n`, 42161 → `500_000_000_000_000n` [제안 후 승인]
- `config/tokens.ts`의 네이티브 ETH 항목 `logoURI`: 세 체인 모두 `https://assets.coingecko.com/coins/images/279/large/ethereum.png` [사용자 결정]
- `config/`의 체인 아이콘 URL: 1 → `https://icons.llamao.fi/icons/chains/rsz_ethereum.jpg`, 8453 → `https://raw.githubusercontent.com/trustwallet/assets/master/blockchains/base/info/logo.png`, 42161 → `https://icons.llamao.fi/icons/chains/rsz_arbitrum.jpg` [사용자 결정]
- `lib/`의 `formatTokenAmount(raw: bigint, decimals: number): string`: DoD-15·DoD-16의 표시 문자열을 돌려준다 [제안 후 승인]
- `lib/`의 `sanitizeAmountInput(input: string, decimals: number): string | null`: 반영할 문자열(쉼표는 소수점으로 바꾼 값)을 돌려주고, 거부하면 `null`을 돌려준다 [제안 후 승인]

## 5. 엣지 케이스와 실패 시나리오

### 5.1 지갑·체인

- EC-1: 선택 체인을 바꾸면 토큰과 금액이 DoD-1의 기본값으로 돌아간다 — 검증: 통합 테스트 [제안 후 승인]
- EC-2: 토큰 모달이 열린 상태에서 선택 체인이 바뀌면 모달이 닫힌다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- EC-3: 미연결·복원 중에도 토큰 선택, 금액 입력, 뒤집기가 연결 상태와 같이 동작한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-4: 미연결·복원 중에는 카드 잔액과 `최대`를 표시하지 않는다 — 검증: 통합 테스트 [제안 후 승인]
- EC-5: 미연결·복원 중의 모달 목록은 잔액 없이 고정 토큰, 나머지 토큰(DoD-10의 순서) 순으로 놓인다 — 검증: 통합 테스트 [제안 후 승인]
- EC-6: 연결 계정이 바뀌면 토큰과 금액을 유지하고 새 계정의 잔액을 표시한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-7: 연결을 해제하면 토큰과 금액을 유지하고 잔액을 숨긴다 — 검증: 통합 테스트 [제안 후 승인]
- EC-8: 지갑 체인이 선택 체인과 달라도 잔액은 선택 체인 기준으로 읽는다 — 검증: 통합 테스트 [제안 후 승인]

### 5.2 잔액 읽기

- EC-9: 같은 계정·체인·토큰으로 성공한 카드 잔액이 없으면(읽는 중이거나 실패) 잔액 자리에 `—`를 표시한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-10: EC-9 상태에서는 `최대`를 비활성화한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-11: EC-9 상태에서는 `insufficient-balance`를 판정하지 않는다 — 검증: 통합 테스트 [제안 후 승인]
- EC-12: 카드 잔액 읽기가 실패하면 오류 문구 없이 다음 주기(15초)에 다시 읽는다. 다시 읽기는 읽기 단위이며 RPC transport의 요청 재시도(F1 설정)는 포함하지 않는다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- EC-13: 이전 모달 잔액(DoD-21)이 없는 상태에서 일괄 읽기 요청(`eth_getBalance`와 aggregate3 묶음) 중 하나라도 실패하면 EC-5와 같은 목록을 표시하고 토큰 선택은 동작한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-14: 일괄 읽기 요청은 성공했으나 개별 토큰의 `balanceOf` 호출이 실패하면 그 행만 잔액 없이 나머지 그룹에 놓인다 — 검증: 통합 테스트, 통합 테스트 (실제 anvil 포크) [제안 후 승인]
- EC-15: 모달이 열린 뒤 잔액이 도착하면 DoD-9 순서로 다시 정렬한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-30: 성공한 카드 잔액이 있으면 다시 읽는 중이거나 다시 읽기가 실패해도 마지막 성공 값을 표시와 판정에 쓴다 — 검증: 통합 테스트 [제안 후 승인]
- EC-31: 이전 모달 잔액(DoD-21)이 있으면 새 일괄 읽기가 실패해도 이전 값을 유지한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-32: 모달 잔액 읽기가 실패하면 모달이 열린 동안 다시 시도하지 않는다. 다시 시도는 읽기 단위이며 RPC transport의 요청 재시도(F1 설정)는 포함하지 않는다 — 검증: 통합 테스트 [제안 후 승인]

### 5.3 목록

- EC-16: 검색 결과가 없으면 `token-search-empty`를 표시한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-17: 토큰 주소를 검색어로 넣으면 결과가 없다 — 검증: 단위 테스트 [사용자 결정]
- EC-18: `logoURI`가 없거나 이미지 로드에 실패하면 모달 행과 카드 토큰 버튼에 심볼 첫 글자를 표시한다 — 검증: 테스트 설계 단계에서 확정 [제안 후 승인]
- EC-28: 검색어가 공백뿐이면 전체 목록을 표시한다 — 검증: 단위 테스트 [제안 후 승인]
- EC-33: 검색어를 비우거나 공백만 남기면 반영 대기 없이 즉시 전체 목록을 표시하고 스켈레톤을 표시하지 않는다 — 검증: 통합 테스트 [사용자 결정]

### 5.4 금액 입력

- EC-19: 보내는 토큰이 미선택이면 금액 입력을 비활성화한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-20: 토큰 decimals를 넘는 소수 자릿수 입력은 반영하지 않고 이전 값을 유지한다 — 검증: 단위 테스트, 통합 테스트 [제안 후 승인]
- EC-21: 숫자·소수점·쉼표 외의 문자나 두 번째 소수점이 든 입력은 반영하지 않고 이전 값을 유지한다 — 검증: 단위 테스트, 통합 테스트 [제안 후 승인]
- EC-22: 붙여넣은 문자열은 전체가 형식에 맞을 때만 반영하고, 아니면 이전 값을 유지한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-23: 금액이 `.`, `0`, `0.00`처럼 값이 0이면 `enter-amount`이고, 입력 문자열은 정규화하지 않는다 — 검증: 통합 테스트 [제안 후 승인]
- EC-24: 잔액이 가스 예약량 이하이거나 0이면 `최대`는 `0`을 넣는다 — 검증: 단위 테스트 [제안 후 승인]
- EC-25: `insufficient-balance`는 표시용 버림값이 아니라 입력 정수와 잔액 정수를 비교해 판정하며, `최대`로 넣은 값은 `insufficient-balance`가 되지 않는다 — 검증: 단위 테스트, 통합 테스트 [제안 후 승인]
- EC-26: ETH 금액이 잔액 이하이면 가스 예약량을 넘더라도 `insufficient-balance`가 아니다 — 검증: 단위 테스트 [제안 후 승인]
- EC-27: 정수부 길이 상한은 없으며, 잔액보다 큰 값은 `insufficient-balance`다 — 검증: 단위 테스트 [제안 후 승인]
- EC-29: DoD-29에서 소수부가 모두 잘리면 소수점도 지운다(decimals 0 토큰에서 `1.5`는 `1`) — 검증: 단위 테스트 [제안 후 승인]
