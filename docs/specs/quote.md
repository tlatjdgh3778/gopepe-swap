# 스펙: quote (QuoterV2 견적·가격 영향·수수료 티어)

- 상태: 완료
- 최종 갱신: 2026-11-13

## 1. 목표

스왑 카드의 입력(`useSwapForm()`)으로 Uniswap V3 QuoterV2 견적을 받아 예상 수령량, 가격 영향, 수수료 티어를 보여 주고, 주 버튼의 `input-valid` 자리를 견적 상태로 대체한다. 고른 티어와 수령량은 F4(최소 수령량)와 F5(스왑)가 읽는 계약(§4.1)이 된다. [제안 후 승인]

### 1.1 화면

- 받는 칸 금액 칸에 예상 수령량을 표시한다 [제안 후 승인]
- 받는 칸 아래에 환율 행을 둔다 [제안 후 승인]
- 환율 행 아래 `견적 정보` 영역에 예상 수령량, 가격 영향, 수수료 티어 행을 이 순서로 둔다. 최소 수령량과 슬리피지 허용치 행은 F4가 추가한다 [제안 후 승인]
- 수수료 티어는 읽기 전용 값이다 [제안 후 승인]
- 가격 영향 등급별 색: `normal`은 `--accent`, `warning`은 `--warning`, `error`는 `--error` [제안 후 승인]
- 주 버튼 문구: `quoting`은 `견적 계산 중…`, `no-route`는 `지원하지 않는 페어`, `quote-error`는 `견적을 가져올 수 없음`, `quote-ready`는 `스왑` [제안 후 승인]
- 시안은 `docs/design/wireframe/`의 시안 A, 디자인 토큰은 `docs/design/README.md`(`--warning: #e8c38b` 포함)를 따른다 [사용자 결정]

## 2. 비목표

- 수수료 티어 수동 선택 [제안 후 승인]
- ETH ↔ WETH 견적과 랩·언랩 (F7) [제안 후 승인]
- 최소 수령량 행, 슬리피지 허용치 행과 설정 (F4). F4의 슬리피지는 0.1%·0.5%·1.0% 프리셋만 쓰고 직접 입력이 없으며 기본값은 0.5%다 [사용자 결정]
- 스왑 실행, approve, 가격 영향에 따른 스왑 차단 (F5) [제안 후 승인]
- 달러 환산과 가스 비용 표시 [제안 후 승인]
- 멀티홉 라우팅 [제안 후 승인]
- 환율 방향 전환 버튼 [제안 후 승인]
- 전송 수수료 토큰과 리베이스 토큰의 견적 보정 [제안 후 승인]
- `@uniswap/v3-sdk`·`@uniswap/sdk-core` 도입 (필요하면 F5에서 판단) [제안 후 승인]
- RPC 프록시 요청 횟수 제한 (F8) [제안 후 승인]
- `eth_call` 가스 상한이 낮은 노드에서 하위 호출이 가스 부족으로 실패하는 경우의 구분. 알려진 한계로 둔다: 상한 50M 노드에서 1e5 ETH 이상이면 일부 티어가 EC-1처럼 후보에서 빠지고, 유동성을 모두 쓰는 금액은 상한 60M 이하 노드에서 `error`가 된다. RPC 운영은 F8에서 다룬다 [사용자 결정]
- wagmi `useSimulateContract`로 견적 조회 [제안 후 승인]

## 3. 완료의 정의

### 3.1 견적 조회

- DoD-1: 두 토큰이 선택되고 금액이 0보다 크면 선택 체인의 QuoterV2로 수수료 티어 100·500·3000·10000을 견적한다 — 검증: 통합 테스트 (RPC fetch 스텁 요청 확인) [제안 후 승인]
- DoD-2: 후보 티어(§5.1 제외 후) 중 수령량이 가장 많은 티어를 고른다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-3: 수령량이 같은 후보가 여럿이면 수수료가 가장 낮은 티어를 고른다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-4: 보내는 토큰이나 받는 토큰이 ETH이면 그 쪽을 선택 체인의 WETH 주소로 바꿔 견적한다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-5: Ethereum 포크 고정 블록에서 ETH→USDC 견적의 티어와 수령량이 QuoterV2를 티어별로 직접 호출해 고른 값과 같다 — 검증: 통합 테스트 (실제 anvil 포크, `test:fork`) [제안 후 승인]
- DoD-6: 지갑 미연결 상태에서도 견적한다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-7: `insufficient-balance` 상태에서도 견적하고 받는 칸과 견적 정보를 표시한다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-8: 요청이 성공하는 경로에서 견적 1회의 RPC 요청은 2건 이하다. RPC transport의 요청 재시도는 세지 않는다 — 검증: 통합 테스트 (RPC fetch 스텁으로 요청 수 집계) [제안 후 승인]
- DoD-9: Base 메인넷에서 ETH→USDC 견적이 표시된다 — 검증: 수동 1회, 결과 기록 [제안 후 승인]
- DoD-10: Arbitrum 메인넷에서 ETH→USDC 견적이 표시된다 — 검증: 수동 1회, 결과 기록 [제안 후 승인]

### 3.2 견적 표시

- DoD-11: `success`이면 받는 칸에 예상 수령량을 `formatTokenAmount` 형식으로 표시한다 — 검증: 통합 테스트, E2E [제안 후 승인]
- DoD-12: `success`이면 `quote-details`에 예상 수령량, 가격 영향, 수수료 티어 행을 표시한다 — 검증: 통합 테스트, E2E [제안 후 승인]
- DoD-13: `success`이면 환율 행 `quote-rate`를 표시한다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-14: `idle`이면 `quote-details`를 렌더링하지 않고 받는 칸은 빈 값(placeholder `0`)이다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-15: `loading`이면 받는 칸 금액, 환율 행, 견적 정보 행 값 자리에 `quote-skeleton`을 표시한다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-40: `idle`, `no-route`, `error`이면 `quote-rate`를 렌더링하지 않는다 — 검증: 통합 테스트 [제안 후 승인]
- DoD-16: 가격 영향은 받는 토큰 기준으로 `(slot0 가격으로 받을 양 − 예상 수령량) / slot0 가격으로 받을 양 × 10000 − fee / 100` bps다. `slot0`은 견적 직전 고른 티어 풀의 값이다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-17: 가격 영향 등급은 표시값(퍼센트 소수 2자리 버림) 기준으로 3% 이하면 `normal`, 3% 초과 15% 이하면 `warning`, 15% 초과면 `error`이며, 음수는 `normal`이다 — 검증: 단위 테스트, 통합 테스트 (`data-severity`) [제안 후 승인]
- DoD-18: 가격 영향 값은 §1.1의 등급별 색으로 표시한다 — 검증: 코드 대조(등급→색 토큰), 수동 1회 화면 대조, 결과 기록 [제안 후 승인]
- DoD-19: 가격 영향은 퍼센트 소수 2자리에서 버려 표시한다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-20: 가격 영향이 0보다 크고 0.01% 미만이면 `<0.01%`로 표시한다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-21: 가격 영향 계산값이 음수이면 `0.00%`로 표시한다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-22: 수수료 티어는 100 → `0.01%`, 500 → `0.05%`, 3000 → `0.3%`, 10000 → `1%`로 표시한다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-23: 환율 행은 `1 {보내는 토큰 심볼} = {값} {받는 토큰 심볼}`이고, 값은 예상 수령량을 보내는 양으로 나눈 체결 평균가를 받는 토큰 decimals의 정수로 버려 계산하고 `formatTokenAmount` 형식으로 표시한다 — 검증: 단위 테스트 [제안 후 승인]
- DoD-24: 표시 문자열 계산에 로캘 API를 쓰지 않으며 결과가 로캘에 따라 달라지지 않는다 — 검증: 단위 테스트(결과의 로캘 무관), 코드 대조(로캘 API 미사용) [제안 후 승인]

## 4. 인터페이스 계약

### 4.1 견적 상태

- 클라이언트 훅 `useSwapQuote()`는 `{ status: "idle" | "loading" | "no-route" | "error" | "success"; quote: SwapQuote | null }`를 돌려준다 [제안 후 승인]
- `SwapQuote`는 `{ amountOut: bigint; fee: 100 | 500 | 3000 | 10000; priceImpactBps: number }`다. `quote`는 `status`가 `success`일 때만 `null`이 아니다 [제안 후 승인]
- `priceImpactBps`는 bps 단위 값이며 정수로 제한하지 않고, 반올림 오차로 음수일 수 있다 [제안 후 승인]
- `idle`은 토큰 미선택 또는 금액이 비었거나 0인 상태, `no-route`는 견적할 직접 풀이 없는 상태(ETH ↔ WETH 포함), `error`는 RPC 실패 상태다 [제안 후 승인]

### 4.2 주 버튼

- `data-testid="primary-button"`의 `data-state` 값: `restoring` | `disconnected` | `select-token` | `enter-amount` | `insufficient-balance` | `quoting` | `no-route` | `quote-error` | `quote-ready`. `input-valid`는 쓰지 않는다 [제안 후 승인]

### 4.3 테스트 식별자

- `quote-details`: 견적 정보 영역. `idle`, `no-route`, `error`에서는 렌더링하지 않는다 [제안 후 승인]
- `quote-amount-out[data-amount-out-raw]`: 예상 수령량 행 [제안 후 승인]
- `quote-fee-tier[data-fee]`: 수수료 티어 행. 값은 `100` | `500` | `3000` | `10000` [제안 후 승인]
- `quote-price-impact[data-severity]`: 가격 영향 행. 값은 `normal` | `warning` | `error` [제안 후 승인]
- `quote-rate`: 환율 행. `idle`, `no-route`, `error`에서는 렌더링하지 않는다 [제안 후 승인]
- `quote-skeleton`: `loading` 중 값 자리의 스켈레톤 [제안 후 승인]
- `token-field[data-side="out"]` 안의 `amount-input[data-amount-out-raw]`: 받는 칸 금액 칸 [제안 후 승인]
- `data-amount-out-raw` 값은 정수 수령량의 10진 문자열이며, `quote`가 `null`이면 속성이 없다 [제안 후 승인]

### 4.4 RPC

- 견적 읽기는 선택 체인 ID를 명시한 `config.getClient({ chainId })`의 클라이언트로 기존 RPC 프록시(`/api/rpc/[chainId]`)를 거친다 [제안 후 승인]
- RPC 프록시의 허용 메서드는 바꾸지 않는다 [제안 후 승인]
- 여러 읽기 호출은 Multicall3 `aggregate3`로 묶는다 [제안 후 승인]

## 5. 엣지 케이스와 실패 시나리오

### 5.1 티어별 결과

- EC-1: 풀이 없어 revert한 티어는 후보에서 뺀다 — 검증: 단위 테스트 [제안 후 승인]
- EC-2: 수령량이 0인 티어는 후보에서 뺀다 — 검증: 단위 테스트 [제안 후 승인]
- EC-3: 풀의 유동성을 모두 써도 입력을 소화하지 못하는 티어는 후보에서 뺀다 — 검증: 단위 테스트 [제안 후 승인]
- EC-4: 남은 후보가 없으면 `no-route`다 — 검증: 단위 테스트, 통합 테스트 (실제 anvil 포크, 풀 없는 페어), E2E (풀 없는 페어) [제안 후 승인]
- EC-5: `no-route`이면 받는 칸을 비우고 `quote-details`를 렌더링하지 않는다 — 검증: 통합 테스트 [제안 후 승인]
- EC-16: 고른 티어 풀의 `slot0` 읽기만 실패하고 견적은 성공하면 `error`다 — 검증: 통합 테스트 [제안 후 승인]

### 5.2 ETH ↔ WETH

- EC-6: 두 토큰이 ETH와 WETH이면 RPC 요청과 입력 반영 대기(300ms) 없이 즉시 `no-route`다 — 검증: 단위 테스트, E2E [제안 후 승인]

### 5.3 RPC 실패

- EC-7: 입력이 바뀐 뒤 첫 견적 읽기가 실패하면 `error`다 — 검증: 통합 테스트 [제안 후 승인]
- EC-8: `error`이면 받는 칸을 비우고 `quote-details`를 렌더링하지 않는다 — 검증: 통합 테스트 [제안 후 승인]
- EC-9: 자동 갱신(DoD-27·DoD-29)의 읽기가 실패하면 `success`와 기존 값을 유지한다 — 검증: 통합 테스트 [제안 후 승인]
- EC-10: EC-9의 실패 뒤 다음 15초 주기에 다시 읽는다 — 검증: 통합 테스트 (가짜 타이머) [제안 후 승인]
- EC-11: 견적 읽기가 실패해도 같은 입력으로 즉시 다시 읽지 않는다(react-query 재시도 없음) — 검증: 통합 테스트 [제안 후 승인]

### 5.4 동시성과 리셋

- EC-12: 체인, 양쪽 토큰, 금액 값(`amountInRaw`) 중 하나가 바뀐 뒤 도착한 이전 입력의 응답은 표시와 상태에 반영하지 않는다 — 검증: 통합 테스트 [제안 후 승인]
- EC-13: 선택 체인을 바꿔 입력이 기본값으로 돌아가면 견적이 사라지고 `idle`이 된다 — 검증: 통합 테스트 [제안 후 승인]
- EC-14: 뒤집기나 토큰 맞바꿈으로 금액이 비면 견적이 사라지고 `idle`이 된다 — 검증: 통합 테스트 [제안 후 승인]

### 5.5 큰 금액

- EC-15: 가격 영향이 `error` 등급이어도 견적을 표시하고 주 버튼은 `quote-ready`다 — 검증: 통합 테스트 [제안 후 승인]
